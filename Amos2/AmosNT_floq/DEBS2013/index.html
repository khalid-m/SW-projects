Grand Challenge: Implementation by Frequently Emitting Parallel Windows and User-Defined Aggregate Functions

The paper

The paper is available here: Grand Challenge: Implementation by Frequently Emitting Parallel Windows and User-Defined Aggregate Functions

Installation

Our implementation can run on any Windows machine.
1) Download Epic.zip to some folder, e.g. C:\ and unzip it there.
2) Download full-game and extract it into 'C:\Epic\debs2013\data\full-game'.
After this the system is ready to run.

Running the DEBS Challenge

To run the entire DEBS Challenge script execute the command:

all.cmd

The DEBS Challenge output streams are saved in the folder 'output' as CSV files named:

q1a.csv (current running statistics)
q1b_1M.csv (aggregate running statistics for 1 minute window)
q1b_5M.csv (aggregate running statistics for 5 minute window)
q1b_20M.csv (aggregate running statistics for 20 minute window)
q1b_landmark.csv (aggregate running statistics for the entire game)
q2playerpossession.csv
q2teampossession_1min.csv
q2teampossession_20min.csv
q2teampossession_5min.csv
q2teampossession_landmark.csv
q3_1M.csv (1 minute heatmap*)
q3_5M.csv (5 minute heatmap*)
q3_10M.csv (10 minute heatmap*)
q3_landmark.csv (The entire game heatmap*)
q4.csv

*Contains the four output streams corresponding to the four grid settings, each stream output is tagged as specified in the paper.

You can also run separately each of the queries with the commands:
q1.cmd
q2.cmd
q3.cmd
q4.cmd

Delay logging

The system has a facility to log the time spent in the system for producing each row in the output CSV files. To run the DEBS Challenge with this delay logging turned on, execute:

all_delays.cmd

When delay propagation is turned on, the system registers when a CSV tuple arrives into the system and propagates this timestamp downstream. In the output CSV log files there are two extra elements first in each row, containing:
i) the wall time when the latest input CSV row that contributed to the result row arrived into the system
ii) the wall time when the output CSV row was printed to the log file.

The delay (in seconds) for producing an output CSV tuple is the difference between the two time stamps.
The wall time is defined as the number of seconds since 14:29:22 on 2013-05-17.

Note that running the system using all_delays.cmd adds around 10% over head. The overhead is due to the high cost in obtaining time-of-day from the OS several times for each incoming tuple. Recall that each tuple communicated and/or written to disk (e.g. high output rate in Q3) triggers a system wall clock query.

Computing the delay statistics per output file

To compute average and standar deviation of the delay per output csv file (as in figure 6 in the paper), after the system has finished executing all_delays.cmd run:

delays.cmd

delays.cmd scans all output CSV files and writes into delay.csv the average and standard deviation of delays per file. We recommend openning the delay.csv in Microsoft Excel where line feed charachters are correctly detected.
