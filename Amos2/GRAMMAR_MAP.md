# AmosQL grammar → Lisp forms

For each rule in [parser.y](AmosNT_floq/system/C/parser.y), the Lisp forms its actions build, and
where a function or macro of that name is defined. Generated by
[tools/gen_grammar_map.py](tools/gen_grammar_map.py). Do not edit by hand; rerun the script.
Context: [KERNEL.md §5](KERNEL.md#5-the-grammars) (parsing) and
[QUERY_COMPILER.md §4.1](QUERY_COMPILER.md#41-from-parsed-statement-to-derived-function) (what
happens when a form is evaluated).

How to read it:

- The parser builds a Lisp list whose first element is the **head** symbol, e.g.
  `select_stmt1` builds `(osql-select …)`. `parse_and_eval` then evaluates that list, so the head is
  called as a function, macro or special form.
- **Defined in** lists `defun`/`defmacro` definitions in `lsp/` ("macro" marks a macro) and C
  built-ins registered in `system/C` ("C"). Several links mean several definitions of that name.
- **Blank** means no Lisp or C definition was found. Most blanks are one of:
  - **AmosQL function names inside query expressions** (`plus`, `times`, `<`, `vref`, `and`, `or`,
    …). These sit inside an `osql-select`/`select` form and are never evaluated as Lisp. The
    query compiler looks them up as AmosQL functions while flattening
    ([QUERY_COMPILER.md §4.2](QUERY_COMPILER.md#42-flattening-overload-resolution-and-type-checks-compileselect)).
  - **Keyword markers** read by an enclosing handler (`distinct`, `into`, `foreach`, `where`,
    `foreign`, `KEY`, `as`, …).
  - **Special forms or built-ins of the binary-only kernel** (`quote`, `commit`, `rollback`, …),
    or names defined some other way, e.g. by `movd`.
- Only heads written as `mksymbol("…")` at the front of `a_list`/`cons`/`listN` are found. Forms
  built through a variable (e.g. `a_list(lispsymbol, …)`) are missed.
